# Серверное тестовое пополнение — где находится код

## Что добавлено

- `backend_v2/migrations/20261021_tools_demo_topups.sql`: таблица `tool_demo_topups` в Supabase. Миграция уже применена к проекту `vvd-cpa`. Она хранит **только тестовые** операции и Telegram ID.
- `backend_v2/tools_marketplace.py`: `GET /tools-market/demo-topups` возвращает тестовый баланс и историю; `POST /tools-market/demo-topups` создаёт тестовую операцию. Комментарий `DEMO TOP-UP` объясняет разделение. Оба маршрута проверяют подписанные Telegram initData.
- `src/pages/tools/marketApi.ts`: `demoTopups` и `createDemoTopup` — клиентские запросы к новым маршрутам.
- `src/pages/tools/MarketplacePages.tsx`: `ToolsTopupPage` отображает серверный тестовый баланс и операции, кнопка имитирует оплату и сохраняет запись на сервере.

## Как проверить

1. Дождаться публикации фронтенда через GitHub Pages **и отдельного деплоя backend_v2 в Render**.
2. В Telegram открыть «Инструменты → Пополнить», создать тестовый счёт и имитировать оплату.
3. Перезапустить Mini App или открыть с другого устройства под **тем же Telegram-аккаунтом** — тестовый баланс должен сохраниться.
4. Старые локальные $5 не перенесены автоматически: это предотвращает возможность считать произвольные локальные записи подтверждёнными серверными операциями.

## Важно

- `tool_demo_topups` **не** `tool_wallets` и **не** `tool_transactions`.
- Никаких запросов к Crypto Pay; `CRYPTO_PAY_API_TOKEN` не используется.
- Тестовый баланс нельзя потратить или вывести. Тестовая кнопка не должна начислять реальные средства.
- Для обновления серверных маршрутов Render должен развернуть свежий коммит; GitHub Pages обновляет только интерфейс.
