# Подготовка реальных пополнений Tools (Crypto Pay)

## Что уже подготовлено

- `backend_v2/migrations/20261021_tools_payment_invoices_preparation.sql`: таблица `tool_payment_invoices` с Telegram ID, USD-суммой, внешним ID счёта, статусом и временными метками. Миграция применена к Supabase `vvd-cpa`.
- `backend_v2/tools_marketplace.py`: существующий `POST /tools-market/topup` намеренно возвращает 503; реальный баланс `tool_wallets` не пополняется.
- `tool_transactions.external_payment_id` уже уникален, но одной уникальности недостаточно без атомарной транзакции.
- `CRYPTO_PAY_API_TOKEN` должен оставаться только в секретах Render; не копировать в frontend, SQL, логи или GitHub.

## Что ещё НЕ реализовано (нельзя просто включить флаг)

1. Серверный адаптер Crypto Pay с обработкой ошибок и проверкой соответствия API провайдера.
2. Создание счёта на сервере только после проверки Telegram initData, диапазона суммы и валюты; хранение provider_invoice_id.
3. Подтверждение оплаченного статуса только через доверенную проверку провайдера (не через UI).
4. Атомарная операция: блокировка счёта, сверка суммы/валюты/провайдера, запись единственной успешной транзакции, увеличение `tool_wallets.available` в одной DB-транзакции.
5. Защита от повторных уведомлений и параллельных запросов; отказ в начислении при любом несовпадении.
6. Учёт просроченных/отменённых счетов и обработка ошибок без повторного списания.
7. UI реального счёта, безопасная ссылка, обновление статуса и отдельная история реальных платежей.
8. Проверка соответствия требованиям провайдера, согласование запуска и включение функции уполномоченным оператором.

## Обязательные ограничения

- Демонстрационные записи из `tool_demo_topups` никогда не конвертируются в реальные деньги.
- Ни один клиентский запрос не может передать `paid` или самостоятельно зачислить средства.
- Не включать реальную оплату на основании наличия токена; нельзя считать миграцию готовой интеграцией.
- В случае отказа провайдера/БД счёт остаётся без начисления до безопасного повторного подтверждения.
